# 梭子 SORTS · 主题设计规范

> 主题内核：**光阴似箭，日月如梭**
> 产品名「梭子」取自织布之梭 —— 梭来往穿梭、经纬交织，正如时间在生命中穿行。箭与梭，都是「快」的意象，因此产品的一切设计都要回答一个问题：**如何让流逝的时间被看见、被留住。**

> **v2 修订说明（2026-09-16 · 前端美术风格改造）**
>
> 本次为**存量方案加强，不是推翻重做**。原方案在主题选型、文案体系、色彩取色、意象提炼四方面均已成立，因此：
>
> - **第一 ~ 四章为 v1 基线，逐字保留，不改动**（主题方向选型、品牌文案体系、设计令牌色值、关键视觉元素）。
> - **第五章起为新增**：国风视觉体系总纲、色彩体系 2.0、字体排版、纹样材质、印章系统、动效、组件语汇、图标插画、时间刻度、无障碍与性能、反模式清单、代码落地。
> - 每项改造的等级（**不动 / 加强 / 新增 / 替换**）见 [§5.0 变更等级表](#50-变更等级表)。
> - 原「六、落地计划」「七、主题在各端的体现」为排期与备忘（非设计资产），已迁移至 [§17](#十七分期落地) / [§18](#十八主题在各端的体现) 并扩充，内容不丢失。

## 一、主题方向选型（三方案对比）

| 方案 | 概念 | 收益 | 风险 | 结论 |
|---|---|---|---|---|
| **A. 织锦流光**（选定） | 时间即织布：日为经、事为纬，日历是一幅正在织成的锦缎 | 与「梭」强绑定，视觉语言独一无二；日历/统计天然适配网格与线性质感；延展性好（皮肤=锦纹） | 隐喻偏抽象，需要克制表达，否则视觉噪音高 | ✅ 主方案 |
| B. 星轨穿梭 | 宇宙、流星、时间轴轨道 | 科技感强、动效好做，前端实现成本低 | 审美同质化严重，与「梭子」品牌名弱关联 | ❌ 放弃 |
| C. 日晷晨昏 | 日晷投影、光影随真实时间流转 | 古典时间感强，仪式感高 | 明暗对比强烈，长时间使用易疲劳；暗色与数据可读性冲突 | ⚠️ 吸收其「时间刻度」元素 |

**最终方案：A 为主，吸收 B 的流光质感、C 的时间刻度感。**
设计原则：**克制的东方感 + 现代数据可读性**，装饰元素只出现在品牌位（登录页、空状态、报告页头），功能区域（日历、计时器、数据表）保持信息密度优先。

## 四、关键视觉元素

1. **梭形（Shuttle）图标**：两端尖、中间宽的纺锤形，用于 logo、加载动画、进度指示。
2. **经纬网格**：日历背景为极淡的经纬线（1px `--sorts-line`），日程块覆盖其上，形成「织锦」观感。
3. **流光动效（shimmer）**：计时中的日程卡片边框做 2s 循环的金色渐变流动 —— 呼应「时光流逝」，仅在活跃项出现，避免干扰。
4. **穿梭过场**：路由切换时，梭形元素从屏幕一侧掠过（200ms），呼应「日月如梭」。
5. **时间刻度**：统计页图表纵轴使用刻度尺样式（吸收方案 C）。

> 以上 5 条为 v1 基线，**意象全部保留**。v2 的职责是把它们从「描述」变成「规格」：第 2 条 → [§8](#八纹样与材质库)；第 3、4 条 → [§10](#十动效规范)；第 5 条 → [§13](#十三时间刻度十二时辰与二十四节气)；第 1 条 → [§12](#十二图标与插画)。

### 5.1 三层材质：纸 · 墨 · 印

国风不等于堆砌符号。本方案的整个视觉体系建立在**三层材质**上，与「织锦」母题同构：

| 层 | 材质 | 传统对应 | 承担 | 出现范围 |
|---|---|---|---|---|
| **底 · 纸** | 月白宣纸（纤维噪点 + 经纬暗纹） | 宣纸 / 素绢 | 页面底、留白、呼吸 | 全局 |
| **中 · 墨** | 徽墨文字与线 | 松烟墨 | 信息、结构、分隔 | 全局 |
| **上 · 印** | 朱砂印 + 缃金描边 | 印泥 / 赤金 | 状态、行动、强调 | **仅功能焦点** |

**核心原则：纸不抢墨，墨不抢印。** 任何一层超载，画面立刻变脏——这是「伪国风」最常见的翻车点：把装饰当成了主角。

### 5.2 三条硬约束（克制原则）

1. **实心朱砂全屏唯一**：主行动按钮 + 实心印章，同屏合计 **≤ 3 处**。朱砂是「注意力」，不是「颜色」。
2. **纹样只做底，不做主**：纹样一律 ≤ 6% 不透明度、或 0.5px 细线，**永不进入视觉焦点**。
3. **宋体不越界**：见 [§7.2](#72-衬线使用边界硬规——本次最重要的具象化)。

### 5.3 与 v1 设计原则的对应

v1 的设计原则是「**克制的东方感 + 现代数据可读性**」。v2 把它拆成了可执行的判据：

- 「克制」→ §5.2 三条硬约束 + §9.3 印章数量纪律 + §8.3 禁用纹样；
- 「可读性」→ §7.2 宋体边界 + §7.3 字阶 + §7.4 数字规范 + §14 对比度门槛。

### 6.5 用色纪律

- **不用纯黑**：`#000000` 在任何位置都禁止，最深用 `#0C131D`（玄青墨 900）。
- **阴影用暖灰，不用黑**：`rgba(27, 42, 65, .06 / .10 / .14)` 三档。黑阴影落在月白底上会发脏。
- **禁止外发光 / 霓虹**：强调靠描边与底色，不靠 glow。
- **一屏色相 ≤ 4**：常态是「墨 / 纸 / 缃金 / 箭青」；朱砂**只在该屏确有「行动或逾期」时**才允许出现。
- **渐变只允许一处**：「穿梭中」的描边流光。其余任何渐变（背景、按钮、文字、头像）一律禁止。

## 七、字体与排版

### 7.1 字体栈

**v1 给定的三套字体栈全部原样沿用**，本次只做两件事：**补末尾的通用 fallback**，以及给变量起统一名字。

```css
/* v1 三套栈：字体族顺序原样不动，仅在末尾补通用兜底 */
--sorts-font-sans:  "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", system-ui, sans-serif;
--sorts-font-mono:  "JetBrains Mono", "SF Mono", ui-monospace, monospace;
--sorts-font-serif: "Source Han Serif SC", "Songti SC", "Noto Serif SC", "STSong", "SimSun", serif;
```

> **透明说明（唯一的非原样照抄处）**：v1 的衬线栈为 `"Source Han Serif SC", "Songti SC", serif`，**前两个字体族与顺序完整保留**，只在末尾追加了 `"Noto Serif SC"`（Android 兜底）、`"STSong"` / `"SimSun"`（旧版 Windows 兜底）。无衬线栈与等宽栈同理，仅补了末尾的 `sans-serif` / `monospace`。**没有任何字体族被删除或调序**——这三套栈对中文环境的覆盖是准确的，本次只是补上跨端缺口。

**为什么是宋不是楷**：宋体横细竖粗、字形方正，与「织锦的经纬线」同构，且在小字号下的结构辨识度远高于楷体。楷体笔画起收装饰多、字面发虚，做标题尚可，做界面必然失手——这是「伪国风」的典型入口。

**字体体积策略（重要）**：**不自托管宋体**。思源宋体全量 6–8MB，为几个标题字加载整套字重是净亏损。策略：

1. 默认走**系统字体链**（Windows→SimSun/Songti SC，macOS→Songti SC，Android→Noto Serif SC），零加载成本；
2. 若评审坚持跨端一致，则**只对品牌用字做子集**（登录页 slogan、报告标题、印章用字，合计 ≤ 150 字），自托管体积可压到 60KB 内；
3. 禁止使用 `@font-face` 引入整套中文衬线。

### 7.2 衬线使用边界（硬规 —— 本次最重要的具象化）

**允许出现宋体的，只有以下四处：**

1. **登录页 slogan / 副标语**（品牌位）；
2. **页面级大标题**（H1，且每页 ≤ 2 个）；
3. **报告正文段落**（今日梭影 / 月度织锦 / 年度织锦，对应 v1 的「报告标题用衬线体，强化东方感」）；
4. **印章内文字**与**空状态主文案**。

**明确禁止出现宋体的**：表格数字、日历格数字、计时器、按钮、表单标签、Toast、导航项、Tag、任何 ≤ 14px 的 UI 文本。

> **依据**：v1 设计原则「克制的东方感 + **现代数据可读性**」。宋体在小字号下笔画对比过强，会显著降低数据区的扫读速度。这条边界把「东方感」约束在品牌壳层，让数据区保持无衬线的中性——**这正是本项目与「满屏书法体」的廉价古风拉开差距的地方**。

### 7.3 字阶（新增，8 级）

v1 未定义字阶，现有实现中出现了 24 / 20 / 17 / 16 / 15 / 14 / 13 / 12 / 11 共 9 个散点字号。本次收敛为 8 级：

| 级别 | 字号 / 行高 | 字重 | 字体 | 用途 |
|---|---|---|---|---|
| `display` | 32 / 40 | 500 | 宋 | 登录 slogan、报告页头 |
| `h1` | 24 / 32 | 500 | 宋 | 页面标题 |
| `h2` | 18 / 26 | 500 | 黑 | 卡片标题 |
| `h3` | 15 / 22 | 500 | 黑 | 区块标题 |
| `body` | 14 / 22 | 400 | 黑 | 正文 |
| `body-sm` | 13 / 20 | 400 | 黑 | 次级信息 |
| `caption` | 12 / 18 | 400 | 黑 | 辅助信息、时间戳 |
| `micro` | 11 / 16 | 500 | 宋 | 印章、极短标签 |

**字重只用 400 / 500 两档**。现有实现里的 `font-weight: 700`（标题、统计数值）在中文无衬线里会显得糊且挤，层级改由**字号 + 颜色对比 + 间距**共同表达，而非靠加粗。

### 7.4 数字与计时

- 所有数字列（统计值、光阴砂余额、时长、日期）使用 `--sorts-font-mono` + `font-variant-numeric: tabular-nums`，保证等宽对齐。
- 计时器字号 28–32px / 字重 500，字符宽度固定，**秒跳不抖动**。
- **禁止数字滚动 / 翻页动效**：长时间使用会产生视觉疲劳（计时器可能连续显示数小时）。
- 时长对外一律「秒」展示，前端 `/60` 保留 1 位小数（与 `docs/PROGRESS.md` 的时长口径一致）。
- 古典数字（十二时辰、二十四节气）用**宋体**，仅出现在计时页与日历页的装饰位，**不承载关键信息**。

## 八、纹样与材质库

### 8.1 四种纹样（严格限四种）

| 纹样 | 传统来源 | 用途 | 规格 | 出现频率 |
|---|---|---|---|---|
| **经纬纹** | 织机经线 × 纬线 | 页面底、日历底、统计图底 | 40px 网距，0.5px 牙色，透明度 60% | 常态 |
| **回纹（雷纹）** | 商周青铜器 | 卡片四角、分割线端头、登录页外框 | 8px 单元等比回形，1px 缃金 | **仅四角** |
| **水波纹（绦波）** | 传统绦带 | 「穿梭中」卡片边框流光、页头分隔 | 1.5px 描边，波长 24px | **仅活跃项** |
| **冰裂纹** | 宋官窑开片 | 空状态、加载态 | 极淡，≤ 4% 不透明度 | **仅空态** |

第 1 种即 v1 第四章第 2 条「经纬网格」的实现规格。

### 8.2 实现方式

- 纹样一律用**内联 SVG** 或 **CSS `background-image` + data-uri**，**禁止 PNG 位图**（缩放模糊 + 体积大）。
- 经纬纹、冰裂纹用 `background-repeat` 平铺，单份资源 ≤ 1KB。
- 回纹作为边框用 `border-image` 或四角 `::before / ::after` 伪元素实现，**不额外增加 DOM**。
- **宣纸质感**：`feTurbulence` 噪点 SVG，`opacity: .035`，`background-blend-mode: multiply`。**禁止用 CSS `filter: blur()`** 造质感（严重掉帧，移动端尤甚）。

### 8.3 禁用纹样（伪国风红线）

龙纹、凤纹、祥云、缠枝莲、万字不到头、大面积山水云海。

**理由**：这些是「戏服」，不是界面。认知负荷高、与数据可读性直接冲突，且是廉价古风的重灾区——一旦用了，产品气质会从「文雅」跌到「景区纪念品」。

## 九、印章系统（本次核心新增）

v1 品牌文案里有「落梭」「穿梭中」这样极具仪式感的动作词，但 v1 没有给出它们的**视觉载体**——结果实现里退化成通用圆角色块徽标（`.status-IN_PROGRESS { background:#FEF3C7 }`）。印章系统就是补上这一环：**让主题动作在视觉上真正成立**。

### 9.1 形制

| 项 | 规格 |
|---|---|
| 形状 | **矩形**（不是圆角胶囊） |
| 宽高比 | 约 1.6 : 1 |
| 圆角 | 3px |
| 内边距 | 4px 9px |
| 字号 / 字重 | 11–12px / 500 |
| 字体 | 宋体（`--sorts-font-serif`） |
| 字距 | `letter-spacing: .12em` |
| 高度 | 26px |

**禁止**：圆形印章、印章底纹、印章旋转、印章做外发光。矩形 + 字距 + 宋体这三个特征已足够传达「印」，再加就是过度设计。

### 9.2 三态

| 形态 | 用色 | 动效 | 语义 |
|---|---|---|---|
| 实心印 | 缃金底 `#C89B3C` + 素白字 | 呼吸（2s，opacity .92 ⇄ 1） | 穿梭中 —— 唯一「活着」的印 |
| 描边印 | 素白底 + 箭青 1px 边 + 箭青字 `#316585` | 无 | 已落梭 —— 终态，视觉更轻 |
| 实心印 | 朱砂底 `#C0563B` + 素白字 | 无 | 逾期 —— 警示 |

### 9.3 数量纪律

- **一屏内实心印章 ≤ 3 枚**（缃金 + 朱砂合计）。
- 列表页**只在「穿梭中 / 逾期」出印**；完成态用描边印；待开始 / 暂停 / 取消不出印（仅靠文字与底色表达）。
- **禁止用印章做分类标签**——分类用 Tag（无底色、只有文字），否则印章会泛滥成噪音，仪式感立刻归零。

## 十、动效规范

v1 第四章第 3、4 条给出了「流光」「穿梭过场」两个意象，本次补齐为完整规格。

### 10.1 动效令牌

| 令牌 | 值 | 用途 |
|---|---|---|
| `--sorts-ease-out` | `cubic-bezier(.32, .72, 0, 1)` | 过场、进场 |
| `--sorts-ease-press` | `cubic-bezier(.2, 1.4, .4, 1)` | 压印、按键（带轻微回弹） |
| `--sorts-dur-fast` | `120ms` | hover / 按下 |
| `--sorts-dur-base` | `220ms` | 过场 / 进场 |
| `--sorts-dur-slow` | `2000ms` | 流光循环 |

### 10.2 五个标志性动效

| 名称 | 触发 | 时长 / 缓动 | 实现要点 |
|---|---|---|---|
| **穿梭过场** | 路由切换 | 220ms / ease-out | 梭形 SVG 从 `translateX(-15%)` 掠至 `115%`；旧页 `opacity 1→0`、新页 `0→1`；仅用 `transform` / `opacity`，结束即移除 `will-change` |
| **流光** | 穿梭中卡片 / 印 | 2000ms 循环 / linear | 1.5px **描边**流光（`conic-gradient` + `mask` 只保留边框）；**不做外发光、不铺底色**——v1「只在活跃项出现，避免干扰」 |
| **落梭压印** | 日程完成 | 180ms / ease-press | 印章 `scale(.9) → 1` + `opacity 0 → 1`；同时列表项左侧 3px 状态条由缃金转箭青 |
| **经纬编织** | 列表 / 日历加载 | 240ms / ease-out，stagger 24ms | 条目 `translateX(-8px)` + `opacity` 依次进场（像梭子推进）；最多 stagger 前 12 项，之后同步进场，避免长列表拖尾 |
| **计时跳动** | 每秒 | 无动画 | 仅更新文本，`tabular-nums` 保证不抖动 |

### 10.3 降级

```css
@media (prefers-reduced-motion: reduce) { /* 关闭过场 / 流光 / 编织，仅保留 opacity 过渡 */ }
```

- 低端机与省电模式下，`conic-gradient` 流光降级为**静态缃金描边**。
- 所有动效**只允许 `transform` / `opacity`**；现有实现中 `.btn:hover { filter: brightness(.9) }` 这类会触发重绘/重排的写法一律替换为背景色 token 切换。

## 十二、图标与插画

- **规格**：24px 网格，1.5px 描边，圆角收笔（`stroke-linecap/linejoin: round`），只用**描边**不用实心（状态点除外）。
- **母题统一**：以「梭」的菱形比例为基准（两端尖、中间宽），视觉重心偏上 0.5px，让同一套图标有统一的「手写感」。
- **着色**：`currentColor`，随 token 切换主题。
- **常用图标（20 个）**：今日、日历、计时、统计、梭灵、锦市、装扮、通知、设置、梭形、落梭、停梭、续梭、经纬、节气、光阴砂、上传、筛选、搜索、更多。
- **插画只画两处**：空状态（一柄梭停在经纬线上）、加载态（梭从左侧缓缓穿出）。**不做成套吉祥物**——成本高且极易显俗。
- **技术**：图标以 Vue 组件形式提供（如 `<IconShuttle />`），打包用 SVG sprite 或 `vite-plugin-svg-icons`；**禁止逐个 `@import`**。
- **现存问题**：`frontend/index.html` 的标题与侧栏共使用 8 类 Emoji 作图标，需全量替换（§16.3 P0-2）。

## 十三、时间刻度：十二时辰与二十四节气

v1 第四章第 5 条只说了「统计页图表纵轴使用刻度尺样式」，本章把「时间刻度」这个意象补全为一套完整的国风时间观——它是本项目**最贴主题的一处细节**（主题即为「时间」）：

1. **刻度尺纵轴**（v1 原条目的实现规格）：统计页纵轴刻度主刻度 8px、次刻度 4px，向右伸出，**替代默认网格线**；数字用等宽字体。
2. **十二时辰**：计时页在计时数字上方以小字显示当前时辰（子丑寅卯…）；**不影响 24 小时制主显示**（时辰是装饰位，不承载关键信息，也不进 `aria-label`）。
3. **二十四节气**：日历页在节气当日格内加极淡标记（宋体 11px / 秋香色 `#E6DCC3`），其余日期不显示；节气当天可在页头给一句短文案（呼应「落梭」的仪式感）。

**纪律**：这三项全部属于**装饰位**——即「拿掉之后功能依然完整」。它们的存在是为了让「时间是织出来的」这件事被感知到，而不是为了展示文化知识。任何影响数据可读性的时间装饰都是过度设计。

### 16.1 目录结构

```
frontend/
├── index.html
├── vite.config.ts
├── package.json
└── src/
    ├── main.ts
    ├── App.vue
    ├── styles/
    │   ├── tokens.css         # 唯一真源：v1 九令牌 + 色阶 + 字阶 + 圆角/间距/动效
    │   ├── theme-night.css    # 夜梭：只覆盖 token，不写第二套组件样式
    │   ├── textures.css       # 宣纸噪点 / 经纬纹 / 回纹 / 冰裂纹（data-uri）
    │   ├── motion.css         # 关键帧 + prefers-reduced-motion 降级
    │   ├── base.css           # reset + 排版默认值（字体栈、字阶）
    │   └── index.css          # 汇总入口：tokens → base → motion → 组件
    ├── components/
    │   ├── ui/                # 15 个原子组件 Button/Input/Card/Modal/Toast/Tabs/Tag/Seal/Skeleton/Empty/Pagination…
    │   └── biz/               # 业务组件 WeaveCalendar/ShuttleTimer/SoulChat/MallCard/NotifyItem…
    ├── icons/                 # 20 个 SVG 图标（Vue 组件，currentColor）
    ├── stores/                # Pinia
    ├── api/                   # axios 封装 + SSE 客户端
    └── views/                 # 页面
```

**分层依赖方向单向**：`styles` ← `components/ui` ← `components/biz` ← `views`。原子组件**不得**引用业务 store。

### 16.2 Token 命名与向后兼容

- 统一前缀 **`--sorts-`**（延续 v1 命名），语义分层：`--sorts-color-*` / `--sorts-font-*` / `--sorts-space-*` / `--sorts-radius-*` / `--sorts-shadow-*` / `--sorts-motion-*`。
- **v1 的 9 个短名继续有效**，作为别名映射到新语义 token：

```css
--sorts-ink:      var(--sorts-color-ink-700);
--sorts-gold:     var(--sorts-color-gold-500);
--sorts-arrow:    var(--sorts-color-arrow-500);
/* …其余 6 枚同理 */
```

这样 v1 令牌表与任何既有引用**都不用改**，新代码直接用语义 token，实现渐进迁移。
- **禁止在组件内写死色值**，一律经 token 取用。
